# 부적 저장·공유 (SCR 1-5 / SCR 2-6)

보관함 화면·날짜·상세 표시의 확정 요구사항은 [SCR 4](SCR_4.md)를 따른다.
이 문서는 SCR 1-5 / SCR 2-6 / SCR 4가 공통으로 사용하는 저장·공유 정책이다.
2026-11-10 복제본에 백엔드 구현 및 내부 테스트를 완료했다. 실제 프론트·외부 API 호출 테스트는 하지 않았다.
실제 요청·응답과 구현 상태는 백엔드 명세·진행표를 따른다.

## 확정된 저장·공유 정책

- 내 부적과 친구에게 받은 부적을 같은 보관함에 표시한다.
- 캘린더는 수령일이 아닌 부적을 만든 날짜를 기준으로 한다.
- 같은 날짜의 여러 부적은 목록에서 선택한다.
- 부적 저장 시 당시 운세 한마디·맞춤 해석·행운의 색을 보존한다.
- 직접 입력한 고민·친구 상황 원문은 부적 저장·공유 시 함께 보존하고 뒷면의 그날의 기록에 표시한다.
- 내 부적은 내 보관함 저장만 지원한다. 내 부적 공유 기능은 제외한다.
- 친구용 부적은 카카오톡 메시지 링크로 공유하고 수령자의 보관함에만 저장한다.
- 공유 링크는 먼저 수령한 한 계정만 받을 수 있고 기간 제한을 두지 않는다.
- 같은 수령 계정이 다시 열면 기존 부적을 보여준다. 다른 계정은 추가로 수령할 수 없다.
- 같은 계정의 같은 부적 중복 저장을 방지한다.
- 부적 삭제와 링크 취소 등 작성된 범위 밖의 기능은 보류한다.
- 본인의 월간 운세는 부적과 별도로 보관하며 친구 운세를 포함하지 않는다.

## 데이터 구조

### `amulets` — 부적 원본

| 필드 | 용도 |
| --- | --- |
| `id` (UUID, PK) | 부적 식별자 |
| `creator_id` (UUID, FK → `auth.users`) | 부적을 만든 사용자 |
| `image_path` (text) | 비공개 Storage 버킷 안의 이미지 경로 |
| `fortune_summary` (text) | 만들 당시의 운세 한마디 |
| `day_message` (text) | 기존 해석 API가 반환한 해석 문장 |
| `action_advice` (text) | 기존 해석 API가 반환한 행동 조언 문장 |
| `record` (text) | 직접 입력한 고민 또는 친구 상황 원문 |
| `lucky_color` (text) | 만들 당시의 행운의 색 |
| `created_date` (date) | 한국 날짜 기준 부적을 만든 날짜. 캘린더 조회 기준 |
| `created_at` (timestamptz) | 생성 시각 |

### `amulet_library` — 사용자 보관함

| 필드 | 용도 |
| --- | --- |
| `id` (UUID, PK) | 보관함 항목 식별자 |
| `owner_id` (UUID, FK → `auth.users`) | 보관함 소유자 |
| `amulet_id` (UUID, FK → `amulets`) | 저장한 부적 |
| `created_at` (timestamptz) | 저장 시각 |

`(owner_id, amulet_id)`를 유일하게 두어 같은 링크를 다시 눌러도 중복 저장되지 않게 한다. 내 부적은 생성 직후 본인 보관함에 넣고, 친구 부적은 수신자가 링크를 열어 수령할 때만 수신자 보관함에 넣는다.

### `amulet_share_links` — 수신 링크

| 필드 | 용도 |
| --- | --- |
| `id` (UUID, PK) | 공유 건 식별자 |
| `amulet_id` (UUID, FK → `amulets`) | 공유할 부적 |
| `sender_id` (UUID, FK → `auth.users`) | 보낸 사용자 |
| `token_hash` (text, unique) | 링크 토큰의 해시값 |
| `recipient_id` (UUID, nullable, FK → `auth.users`) | 최초 수령 계정. 수령 전에는 비어 있음 |
| `created_at` (timestamptz) | 생성 시각 |

링크에는 추측하기 어려운 원본 토큰을 넣고 DB에는 해시만 저장한다. 링크를 아는 로그인 사용자는 수령할 수 있다. 처음 수령한 한 계정만 보관할 수 있고 링크에 기간 제한은 없다. 수령 계정 기록과 보관함 추가는 한 번에 처리하여 동시 요청에서도 한 계정만 수령되게 한다. 링크 취소 기능은 보류한다.

## 이미지 저장소 및 접근

- Supabase Storage에 부적 이미지용 **비공개 버킷**을 만든다. 이미지 파일 자체는 DB에 넣지 않고 `image_path`만 저장한다.
- Android가 완성된 부적 앞면을 이미지 파일로 내보내 백엔드에 전송한다. 백엔드가 PNG 파일인지와 최대 5MB 용량을 검사하고 Storage에 올린다. 당시 운세 한마디·맞춤 해석·행운의 색을 이미지와 함께 저장한다. 고민·친구 상황 원문도 그날의 기록으로 함께 저장한다.
- 보관함 소유자만 자신의 부적 이미지와 의미를 조회할 수 있게 한다. 공유 링크의 토큰만으로 이미지에 직접 접근시키지 않는다. 수신을 완료한 사용자에게 백엔드가 짧은 유효 기간의 이미지 URL을 발급한다.
- 마이그레이션에는 세 테이블, 외래 키·유일 제약, RLS 정책, 버킷 및 Storage 접근 정책을 포함한다. 백엔드는 기존 사용자 JWT로 업로드·서명 URL을 요청한다. 추가 관리자 비밀키를 사용하지 않는다.

## 프론트 연결용 API

모든 API에는 `Authorization: Bearer {access_token}`을 사용한다. 업로드는 `multipart/form-data`로 `image`, `fortune_summary`, `record`, `day_message`, `action_advice`, `lucky_color`, `created_date`를 보내는 초안이다. 필드 검증과 날짜 처리 규격은 [API 명세](../backend/docs/AMULET_API.md)를 따른다.

| 메서드 | 경로 | 요청·결과 |
| --- | --- | --- |
| `POST` | `/amulets` | 내 부적 이미지·당시 결과 업로드 → 원본 생성과 내 보관함 저장, 부적 ID 반환 |
| `POST` | `/amulets/shares` | 친구 부적 이미지·당시 결과 업로드 → 원본과 공유 링크 생성, 카카오톡에 보낼 HTTPS URL 반환. 보낸 사람의 보관함에는 저장하지 않음 |
| `POST` | `/amulets/shares/claim` | 링크 토큰 전달 → 로그인한 수신자의 보관함에 저장, 부적 ID 반환. 같은 사용자의 재요청은 같은 결과 반환 |
| `GET` | `/amulets` | 내 보관함 목록 조회. `month=YYYY-MM` 또는 `date=YYYY-MM-DD` 중 하나 사용 |
| `GET` | `/amulets/{id}` | 내 보관함의 부적 앞면 이미지 URL과 당시 운세 한마디·맞춤 해석·행운의 색·만든 날짜 조회 |

Android는 카카오톡 공유 기능으로 반환된 URL을 메시지에 넣는다. 앱 링크로 들어온 토큰으로 `claim`을 호출하고, 성공하면 반환된 부적 ID로 상세 화면을 열어 앞면을 먼저 보여준다. 로그인하지 않은 상태에서는 수령 API를 호출하지 않고 재방문을 안내한다.

## 구현 전에 정할 값

- 공유 링크에 쓸 도메인과 APK 다운로드 페이지 주소: 아직 없음. 나중에 설정
- 앞면 이미지의 해상도: 프론트 출력에 맞춰 협의. 형식·최대 크기는 PNG·5MB로 확정
- 뒷면 해석은 기존 해석 API의 `day_message`, `action_advice`를 모두 보존·표시한다.
- 카카오톡 메시지 형식과 링크를 앱에서 처리하는 방식

실제 Supabase에 마이그레이션과 비공개 버킷을 적용했다. API는 복제본에 구현했으며 Render 배포는 별도 진행한다.

## 기존 API와 뒷면 정보 연결

2026-11-10 사용자 확인: 해석과 행동 조언을 모두 뒷면에 보존·표시한다.
새 해석을 생성하거나 두 문장을 한 필드로 합치지 않는다.

| 뒷면 영역 | 저장 필드 | 기존 API/입력 출처 |
| --- | --- | --- |
| 오늘의 운세 한마디 본문 | `fortune_summary` | 운세 응답의 `total_comment` |
| 그날의 기록 | `record` | 내 고민의 `concern` 또는 친구 상황의 `situation` |
| AI 맞춤 해석 | `day_message` | 해석 응답의 `day_message` |
| 행동 조언 | `action_advice` | 해석 응답의 `action_advice` |
| 행운의 색 | `lucky_color` | 운세 응답의 `lucky_color` |

위 API는 생성 결과를 반환하고, 부적 저장·공유 API는 그 결과를 별도로 보존한다.
저장 API의 구체적 요청·응답은 [백엔드 API 명세](../backend/docs/AMULET_API.md)를 따른다.
