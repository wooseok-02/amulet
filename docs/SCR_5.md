# 마이페이지 프론트엔드 계약

기준: [마이페이지 · 프론트엔드 작업 및 테스트](https://app.notion.com/p/41b590c0a926812483c6ee87167234fd), 2026-11-17 확인.

## API

- `GET /api/v1/me`: `Authorization: Bearer <accessToken>`, 본문·사용자 ID 없음. 200 JSON의 필수 필드는 `name`, `email`, `birthDate` (`YYYY-MM-DD`), `calendarType` (`SOLAR`/`LUNAR`), `isLeapMonth` (불리언), `birthTime` (`HH:mm` 또는 명시적 null), `gender` (`MALE`/`FEMALE`). 생년월일·성별은 null 불가.
- `POST /api/v1/auth/logout`: 같은 인증 헤더, 요청 본문 없음. 성공은 빈 본문의 204만 허용. 200/202 응답을 성공으로 취급하지 않음.
- 두 요청의 401은 인증 만료. 5xx/통신 실패는 오류를 표시하고 명시적 재시도 허용.
- 로그아웃 204 후 기존 토큰으로 조회하면 401이어야 하며 다른 계정 토큰은 계속 유효해야 함. 서버 구현에서 검증할 항목이며 클라이언트 토큰 삭제만으로 서버 무효화가 검증되지는 않음.

## 화면과 세션

- 내 정보 진입 시 서버 조회. JWT 메타데이터로 실제 회원정보를 대신 표시하지 않음.
- 고정 프로필 아이콘과 ‘오늘도 좋은 흐름과 함께해요’, 응답 이름·이메일, 생년월일·달력 기준·태어난 시간·성별 네 칸.
- `SOLAR/false` → 양력, `LUNAR/false` → 음력 · 평달, `LUNAR/true` → 음력 · 윤달. 시간 null → 모름, MALE → 남성, FEMALE → 여성.
- 필수 값 누락/잘못된 응답은 오류 처리. 임의의 ‘미등록’, 성별/달력 기본값을 채우지 않음.
- 매 조회 시작/화면 이탈/세션 초기화 시 프로필 제거. 지연된 이전 조회와 이전 계정 응답은 버전 검사를 통해 반영하지 않음.
- 로그아웃 중 중복 요청·내비게이션 방지. 204 후 암호화 토큰과 화면 데이터 제거 후 로그인 화면으로 이동. 401도 인증 만료로 이탈. 5xx/통신 실패는 세션 유지 및 오류 표시.
- 디자인 미리보기는 명시적 예시 데이터만 사용하며 서버 로그아웃을 호출하지 않음.
- 자동 로그인 통신 실패 화면의 ‘로그인 정보 지우기’는 별도 로컬 삭제 동작이며 서버 로그아웃 성공으로 간주하지 않음.
- 정보 수정 UI와 상세 정의가 없는 SCR 5-3은 범위 밖. 스키마 변경 없음.

## 검증

`MyPageTest`: 파싱·표시 규칙, 로딩/5xx/401, 계정 전환 후 늦은 응답 차단, 중복 로그아웃 차단, 성공/실패/만료 시 세션 콜백.

`MyPageApiTest`: 로컬 HTTP 서버를 통한 정확한 경로·메서드·Bearer·빈 요청 본문·사용자 ID 미전달 및 빈 204 처리, 401/500/예상 밖 성공 상태 거절.

`MyPageUiTest`: Android 실제 렌더링에서 기본 정보, 달력 세 가지, 시간 모름, 조회 중/실패 시 이전 정보 숨김, 인증 만료 및 로그아웃 중·실패·성공 화면과 별도 테스트 세션 삭제 확인. 서버 응답은 테스트용 ProfileApi로 제어.

2026-11-17 최초 검증 때는 두 API가 404였다. 이후 서버 반영 후 별도 `MyPageLiveIntegrationTest`를 실행하여 실제 계정 3개의 정보·달력·앱 로그인·화면 표시·로그아웃·동일 토큰 재조회 401 및 다른 계정의 토큰 유지까지 통과했다. 상세 범위와 남은 실제 시간 만료/장애 주입 항목은 `MYPAGE_LIVE_INTEGRATION_2026-11-17.md`를 참고한다.
