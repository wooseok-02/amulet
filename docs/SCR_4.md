아래 내용에는 협의된 보관·공유 정책을 반영했다.

## SCR 4-1 · 월별 부적 캘린더 확인

### 표시 정보

- 현재 연도와 월, 월별 캘린더
- 이전 달 / 다음 달 이동 버튼
- 부적이 존재하는 날짜 강조 표시
- 해당 월의 행운의 날: 왼쪽 상단 네잎클로버 아이콘

### 날짜 및 보관 규칙

- 내가 만든 내 부적과 친구에게 받은 부적을 같은 캘린더에 표시한다.
- 모든 부적은 **부적을 만든 날짜**에 표시한다. 수령 날짜를 기준으로 하지 않는다.
- 날짜는 프로젝트 공통 기준인 `Asia/Seoul`을 사용한다.
- 어제 만든 부적을 오늘 받아도 어제 날짜에 표시한다.
- 친구에게 선물하기 위해 만든 부적은 보낸 사람의 보관함에 자동 저장하지 않는다.
- 이전 달 / 다음 달로 이동하면 해당 월의 부적을 표시한다.
- 행운의 날 선정 기준은 미정이며 임의로 계산 방식을 추가하지 않는다.

---

## SCR 4-2 · 날짜 선택 및 부적 확인

### 입력

- 사용자가 캘린더에서 선택한 날짜

### 출력 및 동작

- 선택한 날짜에 만들어진 보관함 부적 목록을 표시한다.
- 같은 날짜의 부적이 여러 개라면 목록에서 모두 확인할 수 있다.
- 목록에서 부적 하나를 선택하면 해당 부적의 상세 화면을 연다.
- 부적이 없는 날짜에는 저장한 부적이 없다는 안내 팝업을 표시한다.

---

## SCR 4-3 · 부적 상세 / 뒷면 확인

### 표시 정보

- 앞면: 완성된 부적 이미지
- 부적을 만든 날짜
- 뒷면: 당시 운세 한마디, 맞춤 해석, 행운의 색

### 저장 및 동작 규칙

- 상세 진입 시 앞면을 먼저 표시한다.
- 부적을 누르면 3D 뒤집기 동작으로 뒷면 정보를 표시한다.
- 부적 저장 시 당시 운세 한마디·맞춤 해석·행운의 색을 함께 보존한다.
- 친구 부적도 보낸 사람이 만들 당시의 결과를 보존하여 수령자에게 보여준다.
- 다시 열 때 운세나 해석을 새로 생성하거나 수령자의 운세로 바꾸지 않는다.
- 직접 입력한 고민·친구 상황 원문은 저장하거나 뒷면에 표시하지 않는다.
- SCR 1·2의 해석 API는 응답만 전달한다. 부적 저장·공유 단계에서 위 결과를
  별도로 보존하는 예외를 적용한다.

---

## SCR 4-4 · 월간 총합 운세 정보

본인의 월간 운세를 보관함에 별도로 저장하고 확인한다.
부적에 들어가는 정보가 아니며 친구 부적 만들기와 친구 운세는 포함하지 않는다.

### 표시 정보

- 월 평균 행운 점수
- 총운 키워드
- AI 종합 운세 해석

### 동작 및 미정 사항

- 보관함 화면 하단에서 본인의 월간 운세 요약을 확인한다.
- 생성 시점, 생성 방식, 평균 점수의 데이터 기준, 저장 방식은 미정이다.
- 부적이나 친구 운세를 월간 운세 집계 대상으로 임의로 사용하지 않는다.

---

## 저장·공유 연결 규칙

- 내 부적은 저장하면 내 보관함에 추가한다.
- 친구 부적은 링크를 받은 사용자가 로그인 후 수령하면 해당 사용자의 보관함에 추가한다.
- 하나의 링크로 여러 사람이 각자 수령할 수 있으며 기간 제한을 두지 않는다.
- 같은 계정이 같은 부적을 다시 수령해도 중복 저장하지 않고 기존 부적을 표시한다.
- 링크 수령 후에는 해당 부적의 앞면을 바로 표시한다.

---

## 개발 시 확인할 사항

- [ ] 내 부적과 받은 부적이 같은 캘린더에 표시되는지
- [ ] 수령일과 관계없이 만든 날짜에 표시되는지
- [ ] 월 이동과 부적 존재 여부 표시가 정상 동작하는지
- [ ] 같은 날짜의 여러 부적을 목록에서 선택할 수 있는지
- [ ] 부적이 없는 날짜에 안내를 표시하고 상세를 열지 않는지
- [ ] 앞면·뒷면 전환과 당시 결과 보존이 정상 동작하는지
- [ ] 고민·친구 상황 원문이 저장·표시되지 않는지
- [ ] 여러 계정의 수령과 같은 계정의 중복 저장 방지가 정상 동작하는지
- [ ] 본인의 월간 운세가 부적·친구 운세와 별도로 저장·표시되는지

> 작성된 범위 밖의 기능은 보류한다. 부적 삭제, 링크 취소, 검색, 정렬,
> 즐겨찾기 등을 이번 범위에 임의로 추가하지 않는다.
> 이 문서는 요구사항이며 구현 완료를 의미하지 않는다. 보관함 API는 아직 구현하지 않았다.
