# 부적 저장·공유 프론트 API 연결 안내 — 최종 전달본

프론트 구현·연결 시 확인할 항목입니다. 체크박스는 프론트 담당자가 완료한 뒤 표시합니다.
검토 기준: 원격 `front` 브랜치 `fcd088baca246b98f44ee9f365fbccd0e96f63a8`.

## 먼저 확인할 연결 순서와 제공 상태

1. 내 부적 저장 → 서버 보관함 목록 → 상세 이미지 조회를 먼저 연결합니다.
2. 친구용 공유 생성 → 링크 전달 → 로그인 후 수령을 연결합니다.
3. 배포 APK와 앱 식별 정보를 전달하고, APK 배포·앱 링크·미설치 안내를 연결합니다.

- 저장·공유·수령·보관함 5개 API는 `back` 병합 및 Render 배포된 규격입니다. 실제 앱 연동 테스트는 아직 하지 않았습니다.
- 공유 생성은 공유 기본 주소 설정 전 `503`입니다. 주소가 확정되면 백엔드가 설정합니다.
- 설치 JSON·APK 다운로드·도메인 연결 API도 PR #4 병합 후 Render 배포를 완료했습니다. APK 파일·앱 식별 정보는 미등록 상태이며 아래 미등록 응답을 처리해야 합니다.
- `/share/{token}`의 HTML 안내 페이지는 제거됐으며 아래 JSON 규격이 적용됩니다. 배포 로그로 서버 시작·Live 상태를 확인했고 실제 API·프론트 연동 테스트는 수행하지 않았습니다.
- 이 문서는 프론트 코드 변경 지침과 API 계약입니다. 프론트 코드 자체를 수정한 것은 아닙니다.

## 현재 Android 코드에서 바꿀 연결 지점

아래 파일 경로는 모두 `android/app/src/main/` 기준입니다.

| 파일·현재 처리 | 프론트 연결 작업 |
| --- | --- |
| `java/com/example/bukku/AppModel.kt`의 `ApiClient.request()` | 현재 JSON 요청만 지원하므로 PNG+텍스트 multipart 업로드를 추가합니다. 기존 인증·토큰 갱신 처리는 재사용합니다. |
| `AppModel.kt`의 `saveDraft()` | 기기 저장 성공을 서버 저장 성공으로 취급하지 않습니다. 내 부적은 저장 API 성공 후 서버 `amulet_id`를 사용합니다. |
| `AppModel.kt`의 `reloadArchive()`와 `CharmModels.kt`의 `CharmStore` | 보관함의 기준 데이터를 서버 목록·상세로 연결합니다. 기존 기기 저장본 자동 업로드·마이그레이션은 이번 API 연결 범위에 포함하지 않습니다. |
| `AppModel.kt`의 `openEditor()` | 현재 두 해석 문장을 `advice` 하나로 합칩니다. 원본 `day_message`, `action_advice`를 각각 유지해 업로드합니다. 합쳐진 문장을 줄바꿈으로 다시 분리하지 않습니다. |
| `CharmArtwork.kt`의 `render()` | 기존 **1000×1400 PNG** 생성 코드를 업로드에 재사용할 수 있습니다. 서버가 문양·테두리를 다시 그리지 않습니다. |
| `CharmArtwork.kt`의 `share()` | 현재 PNG 이미지 전송입니다. 친구 선물은 서버가 반환한 공유 URL을 보내도록 연결합니다. |
| `FeatureUi.kt`의 완성 화면 | 내 부적 공유 버튼과 친구 부적을 보낸 사람 보관함에 저장하는 동작을 합의한 정책에 맞게 조정합니다. |
| `FeatureUi.kt`의 `ArchiveScreen`, `ArchiveDialog` | 서버 월·날짜 목록과 상세를 연결합니다. 저장된 앞면은 `image_url`을 읽고 로컬 문양 데이터로 다시 만들지 않습니다. |
| `AndroidManifest.xml`, `MainActivity.kt` | 현재 HTTPS 링크 수신 처리가 없습니다. 링크 수신·앱 신규 실행 및 이미 실행 중인 경우 토큰 처리·로그인 후 수령을 연결합니다. |

서버 상세에는 문양·테두리·편집용 문구·점수 필드가 없습니다. 앞면은 PNG 자체로 보존합니다.
현재 월간 운세·행운일 예시는 이번 저장·공유 API로 구현하지 않습니다. 친구 부적이나 보관함 점수로 월간 운세를 새로 계산하지 않습니다.


## 공통 연결 규칙

- API 기본 주소: `https://amulet-api.onrender.com`
- 아래 5개 API는 모두 로그인 필요: `Authorization: Bearer {access_token}`
- 사용자 ID는 보내지 않습니다. 서버가 로그인한 계정을 기준으로 처리합니다.
- 저장 시 기존 운세·해석 결과를 전달합니다. 화면을 다시 열 때 AI를 다시 호출하지 않습니다.
- 내 부적 공유·부적 삭제·링크 취소 API는 이번 범위에 없습니다.

| 기능 | 메서드 | 경로 | 성공 코드 |
| --- | --- | --- | --- |
| 내 부적 저장 | POST | `/amulets` | 201 |
| 친구용 공유 링크 생성 | POST | `/amulets/shares` | 201 |
| 선물 받은 부적 수령 | POST | `/amulets/shares/claim` | 200 |
| 월·날짜별 보관함 목록 | GET | `/amulets` | 200 |
| 부적 상세·앞면 이미지 | GET | `/amulets/{amulet_id}` | 200 |

## 공통 업로드 데이터

내 부적 저장과 친구용 공유 생성에서 동일하게 사용합니다.
요청 형식은 JSON이 아닌 `multipart/form-data`입니다. multipart boundary는 HTTP 라이브러리가 설정하도록 합니다.

| 필드 | 타입 | 전달할 값 |
| --- | --- | --- |
| `image` | 파일, MIME `image/png` | 꾸미기를 완료한 앞면 PNG |
| `fortune_summary` | 문자열 | 기존 운세 응답의 `total_comment` |
| `record` | 문자열 | 내 고민 `concern` 또는 친구 상황 `situation` 원문 |
| `day_message` | 문자열 | 기존 해석 응답의 `day_message` |
| `action_advice` | 문자열 | 기존 해석 응답의 `action_advice` |
| `lucky_color` | 문자열 | 기존 운세 응답의 `lucky_color` |
| `created_date` | `YYYY-MM-DD` 문자열 | 부적을 완성한 한국 날짜 |

모든 필드는 필수입니다. 텍스트는 공백만 보낼 수 없고, `record`는 앞뒤 공백 제거 후 1~200자입니다.
PNG는 빈 파일 불가, 최대 **5,242,880바이트(5MiB)**입니다. 현재 Android 출력은 1000×1400이며 그대로 활용할 수 있습니다. 서버는 특정 해상도를 강제하지 않습니다.

텍스트 파트 예시입니다. 아래 JSON 전체를 요청 바디로 보내는 방식은 아닙니다.

```json
{
  "fortune_summary": "준비한 것을 믿고 한 걸음 내디디면 뜻밖의 도움을 만날 수 있는 날이에요.",
  "record": "면접을 앞두고 준비한 말을 잘 전할 수 있을지 걱정했어요.",
  "day_message": "완벽함보다 차분한 진심이 더 오래 기억되는 흐름이에요.",
  "action_advice": "첫 문장을 소리 내어 한 번 연습해보세요.",
  "lucky_color": "초록",
  "created_date": "2026-11-10"
}
```

### 현재 프론트 데이터와 업로드 필드 대응

| API 필드 | 현재 프론트 데이터 출처 |
| --- | --- |
| `image` | `CharmArtwork.render(context, draft)` 결과를 PNG로 인코딩 |
| `fortune_summary` | `draft.message` ← 본인/친구 운세 `total_comment` |
| `record` | `draft.concern` ← `concern` 또는 `friendConcern` |
| `day_message` | 본인 `interpretation` 또는 `friendInterpretation`의 `day_message` 원본 |
| `action_advice` | 같은 해석 응답의 `action_advice` 원본 |
| `lucky_color` | `draft.luckyColor` |
| `created_date` | `draft.date` — 현재 생성 시 한국 날짜 사용 |

`draft.id`는 기기에서 만든 ID입니다. 업로드에는 보내지 않으며, 서버 응답의 `amulet_id`와 구분합니다.
`draft.text`는 앞면에 그리는 문구이므로 PNG에 포함됩니다. `fortune_summary` 대신 보내지 않습니다.
서버에는 친구 이름·관계나 편집용 문양·테두리 값을 추가로 보내지 않습니다.

## 1. 내 부적 저장

**호출 시점:** 내 부적 꾸미기 화면에서 저장 버튼을 눌렀을 때.

- `POST /amulets`
- 헤더: 공통 인증 헤더
- 바디: 공통 업로드 데이터 전체 (`multipart/form-data`)

성공 응답 — `201 Created`:

```json
{
  "amulet_id": "a2cad149-8303-4090-b858-944bc81c0435"
}
```

응답 ID로 상세를 조회할 수 있습니다. 저장한 부적은 본인 보관함에 추가됩니다.

완료 체크:

- [ ] 운세·고민·해석·행동 조언·색을 꾸미기 화면까지 유지한다.
- [ ] 앞면을 PNG로 만들고 파일 용량을 확인한다.
- [ ] 저장 버튼에 multipart 업로드를 연결한다.
- [ ] 요청 중 중복 클릭을 막고, 성공 시 저장 완료를 표시한다.
- [ ] 저장 후 보관함 목록을 갱신한다.
- [ ] 통신이 끊겨 저장 여부가 불명확하면 보관함을 먼저 확인하도록 처리한다. 재저장하면 별도 부적이 생길 수 있다.

## 2. 친구용 공유 링크 생성

**호출 시점:** 친구용 부적 꾸미기를 마치고 공유할 때.

- `POST /amulets/shares`
- 헤더: 공통 인증 헤더
- 바디: 공통 업로드 데이터 전체 (`multipart/form-data`)
- `record`에는 친구 상황 `situation`을 넣습니다.

성공 응답 — `201 Created`:

```json
{
  "amulet_id": "a2cad149-8303-4090-b858-944bc81c0435",
  "share_url": "https://<설정한-공유-도메인>/share/<발급한-토큰>"
}
```

`share_url` 예시는 구조 설명용입니다. 실제로는 서버가 반환한 URL을 그대로 카카오톡 메시지에 넣습니다.
이 부적은 만든 사람의 보관함에 추가되지 않습니다. 먼저 수령한 한 계정만 받을 수 있고 링크는 만료되지 않습니다.

**연결 대기:** 공유 기본 주소가 아직 미정이므로 현재 설정 전에는 `503`을 반환합니다.

완료 체크:

- [ ] 친구 상황과 기존 운세·해석 결과를 multipart로 전달한다.
- [ ] 응답의 `share_url`을 카카오톡 공유 SDK에 연결한다.
- [ ] 공유 취소·실패 시 이미 받은 URL을 유지해 같은 링크로 다시 공유할 수 있게 한다.
- [ ] 공유 생성 성공 후 보낸 사람 보관함에 부적을 임의로 추가하지 않는다.
- [ ] `503`이면 링크가 생성된 것으로 표시하지 않는다.

## 3. 선물 받은 부적 수령

**호출 시점:** 앱이 `/share/{token}` 링크를 받고 로그인 상태를 확인한 뒤.

- `POST /amulets/shares/claim`
- 헤더: 공통 인증 헤더 + `Content-Type: application/json`
- 바디:

```json
{
  "token": "<공유 링크의 /share/ 뒤에 있는 원본 토큰>"
}
```

토큰은 서버가 발급한 43자리 문자열입니다. 프론트에서 해시로 바꾸지 않습니다.

성공 응답 — `200 OK`:

```json
{
  "amulet_id": "a2cad149-8303-4090-b858-944bc81c0435"
}
```

성공하면 해당 ID로 상세를 조회합니다. 같은 계정이 같은 링크를 다시 열면 기존 ID를 반환합니다.
다른 계정이 이미 수령했다면 `409`입니다. 공개 웹페이지 방문만으로는 수령되지 않습니다.

완료 체크:

- [ ] 앱에서 공유 링크의 토큰을 읽는다.
- [ ] 미로그인 상태에서는 수령 요청을 보내지 않고 로그인·회원가입을 안내한다.
- [ ] 로그인 후 원래 링크를 다시 열어 수령하는 흐름을 안내한다.
- [ ] 성공하면 보관함을 갱신하고 상세 화면에서 앞면을 먼저 표시한다.
- [ ] 같은 링크를 다시 열어도 보관함 항목을 중복 추가하지 않는다.
- [ ] `409`이면 “다른 계정이 이미 받은 부적”을 안내한다.
- [ ] `404`이면 부적 또는 링크를 찾을 수 없음을 안내한다.

## 4. 월·날짜별 보관함 조회

**호출 시점:** 보관함 진입·월 변경·달력 날짜 선택 시.

- 월 조회: `GET /amulets?month=2026-11`
- 날짜 조회: `GET /amulets?date=2026-11-10`
- 헤더: 공통 인증 헤더
- 요청 바디 없음. `month`와 `date` 중 **하나만** 보냅니다.
- 조회 기준은 수령일이 아닌 부적의 `created_date`입니다.

성공 응답 — `200 OK`:

```json
{
  "items": [
    {
      "amulet_id": "a2cad149-8303-4090-b858-944bc81c0435",
      "created_date": "2026-11-10",
      "fortune_summary": "준비한 것을 믿고 한 걸음 내디디면 뜻밖의 도움을 만날 수 있는 날이에요.",
      "record": "면접을 앞두고 준비한 말을 잘 전할 수 있을지 걱정했어요.",
      "day_message": "완벽함보다 차분한 진심이 더 오래 기억되는 흐름이에요.",
      "action_advice": "첫 문장을 소리 내어 한 번 연습해보세요.",
      "lucky_color": "초록"
    }
  ]
}
```

항목이 없으면 `200`과 `{"items": []}`를 반환합니다. 목록 응답에는 이미지 URL이 없습니다.

완료 체크:

- [ ] 선택한 월을 `YYYY-MM`으로 보내 부적이 있는 날짜를 표시한다.
- [ ] 선택한 날짜를 `YYYY-MM-DD`로 보내 해당 날짜 목록을 보여준다.
- [ ] 같은 날짜의 여러 부적을 각각 선택할 수 있게 한다.
- [ ] 빈 목록이면 저장한 부적이 없음을 안내한다.
- [ ] 항목의 `amulet_id`로 상세 API를 연결한다.

## 5. 부적 상세·앞뒷면 표시

**호출 시점:** 보관함 항목 선택 또는 선물 수령 성공 후.

- `GET /amulets/{amulet_id}`
- 예: `/amulets/a2cad149-8303-4090-b858-944bc81c0435`
- 헤더: 공통 인증 헤더
- 요청 바디 없음

성공 응답 — `200 OK`:

```json
{
  "amulet_id": "a2cad149-8303-4090-b858-944bc81c0435",
  "created_date": "2026-11-10",
  "fortune_summary": "준비한 것을 믿고 한 걸음 내디디면 뜻밖의 도움을 만날 수 있는 날이에요.",
  "record": "면접을 앞두고 준비한 말을 잘 전할 수 있을지 걱정했어요.",
  "day_message": "완벽함보다 차분한 진심이 더 오래 기억되는 흐름이에요.",
  "action_advice": "첫 문장을 소리 내어 한 번 연습해보세요.",
  "lucky_color": "초록",
  "image_url": "<서버가 발급한 이미지 임시 URL>"
}
```

| 화면 표시 | 응답 필드 |
| --- | --- |
| 날짜 | `created_date` |
| 앞면 이미지 | `image_url` |
| 오늘의 운세 한마디 본문 | `fortune_summary` |
| 그날의 기록 | `record` |
| 맞춤 해석 | `day_message` |
| 행동 조언 | `action_advice` |
| 행운의 색 | `lucky_color` |

이미지 URL의 유효시간은 **5분**입니다. 영구 주소로 저장하지 말고 상세를 다시 열 때 새로 받습니다.
본인 보관함에 없는 부적은 `404`입니다.

완료 체크:

- [ ] 상세 진입 시 앞면 이미지를 먼저 표시한다.
- [ ] 부적을 누르면 뒷면으로 뒤집고 위 필드를 표시한다.
- [ ] 해석과 행동 조언을 둘 다 표시한다.
- [ ] 뒷면에는 저장 당시 값을 사용하고 운세·AI를 새로 요청하지 않는다.
- [ ] 임시 이미지 URL 만료 시 상세를 다시 조회해 새 URL을 받는다.

## 6. 설치 정보·APK 다운로드 API

화면은 전부 프론트에서 구현합니다. 서버는 HTML을 반환하지 않습니다.
아래 API는 미설치 사용자도 사용하므로 로그인 헤더가 필요 없습니다.

### 설치 정보 조회

`GET /app/install` — 요청 바디 없음. 성공 `200 OK`.

APK 등록 시:

```json
{
  "apk_available": true,
  "download_url": "https://amulet-api.onrender.com/app/download"
}
```

APK 미등록 시에도 `200`:

```json
{
  "apk_available": false,
  "download_url": null
}
```

### 공유 링크 진입 시 설치 정보

`GET /share/{token}` — 위 설치 정보와 동일한 JSON 응답입니다. HTML 화면이 아닙니다.
토큰 형식이 잘못되면 `404`입니다. 이 GET은 실제 링크 존재 여부를 검증하지 않으며 부적 조회·수령도 하지 않습니다.
실제 수령 가능 여부는 로그인 후 `POST /amulets/shares/claim`으로 판단합니다.

### APK 다운로드

`GET /app/download` — 요청 바디 없음.

- 서버에 APK 파일이 등록되면 `200`으로 파일을 내려줍니다. JSON 응답이 아닙니다.
- MIME: `application/vnd.android.package-archive`, 다운로드 파일명: `bukku.apk`.
- 외부 파일 저장소 방식이면 `307`로 APK 주소에 이동합니다. 다운로드 시 리다이렉트를 허용합니다.
- 미등록이면 `503`과 `{"detail":"앱 설치 파일이 아직 등록되지 않았습니다."}`를 반환합니다.
- 실제 설치는 사용자가 Android의 설치 절차로 진행합니다.

### 담당 범위

| 작업 | 담당 |
| --- | --- |
| 서명된 배포 APK 빌드 후 전달 | 프론트 |
| APK 보관·다운로드 제공·설치 정보 API | 백엔드 |
| 설치 안내 화면·다운로드 버튼·앱 화면 | 프론트 |
| 공유 링크·토큰 발급, 저장·수령·접근 권한 | 백엔드 |
| Android Manifest의 링크 수신·앱 화면 이동 | 프론트 |
| 공유 도메인의 `/.well-known/assetlinks.json` 제공 | 백엔드, 프론트가 앱 식별 정보 전달 |

`GET /.well-known/assetlinks.json`은 등록된 패키지명·서명 SHA-256으로 Android 연결 JSON을 반환합니다. 미등록이면 `503`입니다. 별도 공유 도메인을 사용한다면 그 도메인에서도 해당 파일이 제공되도록 배포를 맞춰야 합니다.

**프론트에서 전달할 자료:**

| 항목 | 확인된 현재 상태·필요한 전달 |
| --- | --- |
| 설치 배포할 서명 APK 파일 | 저장소에는 APK가 없습니다. Android README의 `app-debug.apk`는 개발자 PC의 로컬 경로입니다. 배포할 실제 파일을 전달합니다. |
| 사용할 패키지명 | 현재 `applicationId`는 `com.example.bukku`이고 README에는 임시값으로 명시돼 있습니다. 유지 또는 변경 여부와 실제 배포 APK의 값을 알려줍니다. |
| 배포 APK 서명 인증서 SHA-256 | 실제 배포 APK에 사용한 인증서 지문을 전달합니다. 서명 비밀키·비밀번호는 전달하지 않습니다. |

APK 보관·다운로드 설정과 도메인 연결 JSON 등록은 백엔드가 처리합니다.
공유 주소와 미설치 시 진입 방식은 담당자 간 연결이 필요합니다. 설치 안내 화면이 필요하면 프론트에서 구현합니다. 별도 웹 화면 코드는 현재 `front` 브랜치에서 확인되지 않았습니다.
API 서버의 `/share/{token}`은 JSON을 반환하므로 이 주소만 카카오톡에 넣어 미설치 사용자 안내까지 완성됐다고 처리하면 안 됩니다. 화면 없이 APK 다운로드로 바로 이동하는 방식은 검토안이며 현재 구현·확정된 동작이 아닙니다. 공유 주소를 임의 설정하지 않습니다.

완료 체크:

- [ ] 서명 APK와 패키지명·배포 인증서 SHA-256을 백엔드에 전달한다.
- [ ] 프론트 설치 안내 화면에서 설치 정보 API를 연결한다.
- [ ] `apk_available`이 true이면 다운로드 버튼에 `download_url`을 연결한다.
- [ ] 미등록이면 APK 준비 중 상태를 표시한다.
- [ ] 공유 화면 주소와 API 호출 경로를 맞춘다.
- [ ] Android 링크 수신 설정과 공유 도메인의 연결 파일을 맞춘다.
- [ ] 설치·로그인 후 원래 링크를 다시 누르도록 안내한다.

## 공통 오류 처리

일반 오류 응답 예시:

```json
{
  "detail": "오류 설명"
}
```

현재 서버의 검증 오류도 `detail` 문자열로 반환합니다. HTTP 상태 코드로 우선 분기합니다.

| HTTP | 프론트 처리 |
| --- | --- |
| 401 | 로그인 정보 확인·기존 인증 만료 처리 |
| 404 | 부적 또는 링크를 찾을 수 없다는 안내 |
| 409 | 다른 계정이 이미 수령했다는 안내 |
| 413 | PNG 용량을 줄이도록 안내 |
| 415 | 정상 PNG 파일인지 확인하도록 안내 |
| 422 | 필수 필드·기록 길이·날짜 형식 확인 |
| 503 | 저장소 또는 공유 설정을 사용할 수 없다는 안내 |

- [ ] 로딩·성공·실패 상태를 구분해 표시한다.
- [ ] 오류의 `detail` 문자열과 HTTP 상태 코드를 처리한다.
- [ ] 저장·공유 생성 요청이 시간 초과됐을 때 무조건 자동 재전송하지 않는다. 중복 생성 가능성을 고려한다.
