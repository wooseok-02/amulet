# 마이페이지 구현 및 검증 결과

2026-11-17 (Asia/Seoul). 기준: [마이페이지 · 프론트엔드 작업 및 테스트](https://app.notion.com/p/41b590c0a926812483c6ee87167234fd).

## 구현

- 내 정보 진입 시 `GET /api/v1/me`를 호출하고 응답으로 이름·이메일·생년월일·달력 기준·태어난 시간·성별을 표시한다. 실제 회원정보를 JWT 메타데이터에서 추정하던 코드를 제거했다.
- 필수 문자열/날짜/성별/달력/윤달 불리언을 검증한다. 시간 null만 ‘모름’으로 표시한다. 양력·음력 평달·음력 윤달, 남성·여성 문구를 계약대로 표시한다.
- 조회 시작·조회 실패·화면 이탈·인증 만료 시 이전 프로필을 숨기고, 이전 요청/이전 계정의 지연 응답을 무시한다. 서버 오류는 명시적 재시도를 제공한다.
- `POST /api/v1/auth/logout`은 Bearer 인증, 빈 요청 본문으로 전송한다. 빈 204만 성공으로 인정한다. 중복 요청을 막고 204 후 암호화 토큰·프로필·앱 상태를 삭제하여 로그인 화면으로 이동한다. 401은 인증 만료, 그 외 실패는 세션 유지 및 오류 표시다.
- 프로필 아이콘과 고정 인사말을 추가했다. 정보 수정 UI·SCR 5-3·DB 스키마 변경은 포함하지 않았다. 미리보기와 자동 로그인 실패 시 로컬 세션 삭제는 서버 로그아웃과 구분했다.

기기: 이번 작업에서 만든 `Bukku_Install_20261117`, Android API 36 / x86_64. 사용자의 기존 테스트 AVD 데이터를 삭제하지 않았다. 화면 시험은 debug AndroidTest APK를 배포 인증서로 재서명하여 실제 0.2.1 release 앱을 대상으로 실행했다. 시험 응답은 테스트용 `ProfileApi`가 제공하며 운영 서버 성공을 의미하지 않는다. 로그아웃 저장소 검증은 별도의 테스트용 암호화 저장소를 사용한다.

최초 기기 실행은 System UI ANR로 화면 2개가 실패했고 세션 3개는 통과했다. 두 번째 실행은 화면 접근성 조회가 일시적으로 빈 값을 반환하여 화면 1개가 실패했다. 특정 에뮬레이터 시스템 ANR만 처리하고 같은 화면에서 모든 필수 문구가 확인될 때까지 기다리도록 시험을 보완한 후, 최종 화면 2개가 모두 통과했다. 부꾸 앱의 오류 창은 자동으로 닫지 않는다. 실패 회차는 통과 수에 포함하지 않았다.

출력 폴더의 유효 캡처 6장에서는 로딩, 음력 평달·윤달, 조회 실패, 로그아웃 중·실패 상태를 육안 확인했다. 양력·시간 모름·여성은 로그아웃 중/실패 캡처에도 표시된다. 최초 양력·만료·로그아웃 완료 캡처는 전환 프레임 때문에 검증 자료에서 제외했다. 해당 기능의 텍스트/상태 검증은 통과했으나 로그인 화면 전체의 시각적 E2E를 대신하지 않는다.

## 실서버 대기 — 완료로 처리하지 않음

현재 설정된 서버 `https://amulet-api.onrender.com`에서 다음 결과를 확인했다.

- 인증 없는 `GET /api/v1/me`: 404 `{"detail":"Not Found"}`
- 인증 없는 `POST /api/v1/auth/logout`: 404 `{"detail":"Not Found"}`
- 공개 OpenAPI의 경로 목록에도 해당 경로가 없었다.

따라서 실서버 로그인 → 프로필 표시, A·B 계정 격리, 정상 서명된 만료 토큰 거절, 로그아웃 204 후 같은 A 토큰 조회 401 및 B 토큰 200 유지는 미확인이다. 서버가 해당 경로를 제공한 뒤 별도 검증해야 한다. 이번 작업에서는 운영 테스트 계정/회원 데이터를 새로 만들거나 서버 스키마·설정을 수정하지 않았다.

로컬 구현·모의 HTTP·모의 응답 기반 기기 검증은 완료했지만 실서버 통합 완료로 표시하지 않는다. GitHub Releases와 기존 공개 다운로드 링크는 갱신하지 않았다.
