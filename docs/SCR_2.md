## SCR 2-1 · 친구 기본 정보 입력

사용자가 친구의 운세를 확인하기 위해 친구 정보를 직접 입력한다.

### Android 화면 입력

- 친구 이름 또는 별명
- 생년월일
- 양력 / 음력
- 음력 선택 시 윤달 여부
- 태어난 시간 또는 시간 모름
- 친구와의 관계: 친구 / 연인 / 가족 / 동료
- 성별: 여성 / 남성 / 선택 안 함

### 사용 규칙

- 이름·별명과 관계는 Android 화면 표시용으로만 사용한다.
- 이름·별명과 관계는 백엔드나 OpenAI에 전달하지 않는다.
- 시간 모름은 `birth_time: null`로 전달한다.
- 성별 선택 안 함은 `gender: null`로 전달한다.
- 모든 입력값은 DB에 저장하지 않고 현재 Android 화면 상태로만 유지한다.

## SCR 2-2 · 친구 오늘 운세 확인

친구의 사주 정보와 한국 날짜를 OpenAI에 전달해 친구용 오늘 운세를 생성한다.

### 제공 정보

- 날짜
- 운세 제목 한 줄
- 총합 운 코멘트 한 줄
- 총운 점수: 0~100
- 행운 숫자 1개: 0~10
- 행운 색: 색 이름만 제공
- 응원 행동 한 줄

내 운세 화면의 애정운·금전운·직장운·학업운·건강운 세부 점수는 제공하지 않는다.
친구 운세 생성 API는 결과를 DB에 저장하지 않으므로 다시 호출하면 새 결과가 생성될 수 있다.
단, 부적을 공유할 때는 뒷면에 필요한 당시 결과를 별도로 보존한다.

---

## SCR 2-3 · 친구 상황 입력

### 상황 선택

- 전체
- 연애
- 금전
- 취업
- 학업
- 건강
- 인간관계

### 친구의 상황

- 직접 입력
- 최대 200자
- 빈 내용은 허용하지 않음

내 고민 입력과 달리 현재 마음 상태는 선택하지 않는다. 입력값은 DB에 저장하지
않는다.

## SCR 2-4 · AI 맞춤 해석

친구의 사주 정보, 생성된 오늘 운세, 상황 분야와 상황 내용을 OpenAI에 전달한다.

### 출력

- 친구에게 전할 해석 한 줄
- 친구가 실천할 수 있는 행동 조언 한 줄

해석 API는 결과를 DB에 저장하지 않고 응답으로만 전달한다. 다만 부적을
저장·공유할 때는 당시 운세 한마디·맞춤 해석·행운의 색을 별도로 보존한다.
직접 입력한 고민·친구 상황 원문은 보존하지 않는다.
상세 규칙은 [보관함](SCR_4.md)과 [저장·공유 초안](AMULET_STORAGE_AND_SHARING.md)을 따른다.

---

## SCR 2-5 · 부적 꾸미기

AI 맞춤 해석 이후의 부적 꾸미기는 SCR 1-4와 같은 방식으로 Android 앱에서
처리한다. 부적을 만드는 과정에는 백엔드가 개입하지 않는다.

---

## SCR 2 백엔드 API

모든 요청에 로그인 후 받은 Access Token을 보낸다.

```http
Authorization: Bearer {access_token}
```

| 기능 | Method | Endpoint |
| --- | --- | --- |
| 친구 오늘 운세 생성 | `POST` | `/fortune/friend/today` |
| 친구 상황 맞춤 해석 | `POST` | `/fortune/friend/interpret` |

두 번째 요청에는 Android가 임시로 보관 중인 친구 정보와 첫 번째 API에서 받은
친구 운세를 함께 전달한다. 운세·해석 API는 SCR 2 데이터를 보관하지 않는다.
후속 부적 공유 단계에서는 위에 명시한 뒷면 결과만 별도로 보존한다.

백엔드 내부 테스트를 완료했다. 2026-10-14 가상 입력으로 실제 OpenAI 생성 코드
호출(친구 운세·친구 상황 해석)을 확인했다. 인증·Android를 포함한 통합 테스트는
남아 있다. 상세 결과와 연결 체크리스트는 [작업 진행사항](../WORK_PROGRESS.md)을
참고한다.
