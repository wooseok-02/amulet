# Android 로그인·회원가입·메인 구현

## 기준

루트 README, AUTH_INTEGRATION, SCR_3, SCR_1과 사용자가 제공한 Notion 및 Figma 캡처를 기준으로 구현했다.
Android 코드는 `android/`에 있으며 단순한 Compose → AppModel(ViewModel) → API/세션 저장 구조다.

## 현재 구현

- 로그인과 회원가입 화면, 검증과 오류 메시지, 날짜/시간 선택, 음력 윤달 선택.
- 서버의 JWT를 인증 헤더로 전송하고 만료/401 시 갱신 후 한 번 재시도한다.
- Refresh Token과 Access Token을 Android Keystore 키로 AES-GCM 암호화하여 로컬 저장한다.
- 앱 재실행 시 자동 로그인, 로컬 로그아웃, 갱신된 두 토큰 저장.
- 네트워크 오류는 저장된 세션을 유지하며 자동 로그인 재시도를 제공한다.
- 오늘 운세의 점수/행운 정보와 고민 입력, 상황/마음 선택, AI 해석.
- 제공된 캡처의 로고, 점무늬, 색상과 테두리를 사용하고 휴대폰 너비에 맞게 배치했다.
- API가 없는 알림과 보관함은 예시 화면이다. 친구 선물과 부적 편집은 후속 구현 안내다.

## API 및 미리보기

실제 서버 주소가 문서에 없으므로 사용자가 내 정보 → 서버 설정에서 HTTPS 주소를 입력한다.
`/auth/signup`, `/auth/login`, `/auth/refresh`, `/fortune/today`, `/fortune/interpret`를 호출한다.
실제 인증을 더미 로그인으로 처리하지 않는다. 디자인 미리보기는 별도 상태로 표시하며 예시 운세와 해석만 제공한다.
서버 실패 시 예시 운세로 조용히 대체하지 않는다.
프론트는 토큰의 유효기간을 무제한으로 변경하지 않는다. Supabase 인증 정책은 백엔드 담당 영역이다.

## 검증 및 남은 항목

APK 빌드와 회원가입 검증/API 계약 단위 테스트 10개를 통과했다.
에뮬레이터에서 로그인/회원가입 화면 이동, 스크롤, 음력 윤달 표시, 입력 오류와 메인 예시 화면을 확인했다.
Android Instrumentation으로 세션 암호화 저장/복원, 토큰 교체/삭제, 손상된 저장값 제거 테스트 3개도 통과했다.
실제 서버의 계정/프로필 생성, 중복 이메일 응답, 토큰 갱신/만료 정책과 실제 Android 기기 검증은 서버 주소 제공 이후에 확인해야 한다.
정확한 원본 폰트와 독립 로고 파일을 받으면 교체한다. 현재 한글 제목은 Noto Serif KR을 사용한다.
패키지 이름 `com.example.bukku`는 개발용이다.
OneDrive와 한글 경로의 도구 문제를 피하는 이 컴퓨터 전용 경로는 android/README.md에 기록했다.
